# 중요 — 나중에 반드시 처리할 것

## 음성 채널 입장 권한 발급 (엿듣기 방지)

작성: 2026-10-12 / 상태: **미구현(보류)** — 출시 전 과제

### 지금의 문제
- 음성 채널 이름은 `lobby_방코드`, `alive_방코드`, `dead_방코드`로, 방 코드만 알면 누구나 만들 수 있다.
- 현재는 Unity 인증으로 로그인한 플레이어라면 **어떤 채널이든 들어갈 수 있다.** 채널에 들어갈 자격을 검사하는 곳이 없다.
- "누가 들리는지"(거리, 벽, 생존/유령)는 **듣는 쪽 클라이언트가 음량을 0으로 낮추는 방식**이다(`InGameVoiceProximity`). 소리 자체는 전부 받고 있다.

그래서 변조된 클라이언트는 다음이 가능하다.
1. 생존자인 채로 `dead_` 채널에 들어가 유령들의 대화를 듣는다(누가 죽었는지, 범인이 누구인지).
2. 거리·벽 제한을 끄고 생존자 전원의 대화를 듣는다.
3. 죽은 뒤에도 `alive_` 채널에 말한다.
4. 방 코드만 아는 외부인이 게임에 접속하지 않고 음성만 듣는다.

### 해결 방향
Vivox는 로그인·채널 입장 때마다 **입장 토큰**을 요구할 수 있다. 이 토큰을 클라이언트가 아니라 **우리 서버가 서명해서 발급**하면, 서버가 허락한 채널에만 들어갈 수 있다.

1. 토큰 서명 키는 서버에만 둔다(클라이언트·저장소에 넣지 않는다).
2. 클라이언트는 채널에 들어가기 전에 서버에 "이 채널 토큰을 달라"고 요청한다.
3. 서버는 요청한 플레이어가 그 방의 구성원인지, 그 채널에 들어갈 상태인지(생존자 → `alive_`, 유령 → `dead_` + `alive_` 듣기) 확인하고 토큰을 준다. 토큰은 짧게(수십 초) 만료시킨다.
4. Unity 쪽은 토큰 발급기(`IVivoxTokenProvider`)를 구현해 `VivoxService`에 등록한다. 등록 시점과 정확한 사용법은 설치된 SDK(16.11.0) 문서로 확인 필요.

### 이 프로젝트에서 따로 풀어야 할 점
- **게임 서버가 플레이어 PC(방장)다.** 방장에게 서명 키를 줄 수 없으므로 토큰은 Node 방 코드 서버(`Server/`)가 발급해야 한다.
- Node 서버는 지금 "누가 살아 있는지"를 모른다. 방장이 생존/사망 상태를 Node 서버에 알려야 하는데, **방장 자신이 변조된 클라이언트일 수 있다.** 방장까지 막으려면 전용 서버가 필요하다(접속 구조 결정과 함께 정해야 함).
- 토큰으로 막을 수 있는 것은 **채널 입장**까지다. 같은 `alive_` 채널 안에서 거리·벽을 무시하고 듣는 것(위 2번)은 토큰으로 막지 못한다. 이것까지 막으려면 가까운 사람끼리만 같은 채널에 두거나, Vivox의 위치 기반 채널을 서버가 정한 위치로 쓰는 방식이 필요하다.
- 죽은 사람을 `alive_` 채널에서 말하지 못하게 하려면 서버가 강제로 음소거/퇴장시키는 토큰(권한)도 필요하다.

### 우선순위 제안
1. `dead_` 채널 입장 제한(유령 대화 엿듣기) — 게임 결과에 가장 큰 영향
2. 방 구성원이 아닌 사람의 입장 차단
3. 거리·벽 무시 듣기 방지 — 구조 변경이 커서 마지막
