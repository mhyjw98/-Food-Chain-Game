# 미니맵 구현 - Claude Code 작업 프롬프트 (어몽어스 / 구스구스덕 스타일)

## 목표
Mirror 기반 멀티플레이 소셜 서바이벌 게임("먹이사슬")에 어몽어스/구스구스덕 느낌의
미니맵을 추가한다. 우측하단에 항상 떠 있는 작은 미니맵과, 클릭 혹은 특정 키로 여닫는 전체 맵 오버레이를 만든다.

## 프로젝트 전제
- Unity 6000.3.22f1, URP, 2D 탑다운, Mirror 96.0.1
- 2D Light + POV 마스크 기반 시야 시스템이 이미 있음
- 오브젝트 상호작용 미션 시스템, 플레이어 간 사냥 시스템이 이미 있음
- 포식자 / 피식자 역할이 있고, 7명 이상이 플레이함
- 작업 브랜치는 mainc

## 0단계 - 분석만 (이 단계에서는 파일을 수정하지 마)

```
아래 항목을 코드와 씬에서 확인해서 요약해줘. 수정은 하지 마.
1) 맵 구조: 씬 이름, 맵이 타일맵인지 스프라이트인지, 맵 전체 경계(월드 좌표 Bounds)
2) 플레이어 프리팹과 플레이어 NetworkBehaviour 스크립트, isLocalPlayer 처리 방식
3) 미션 오브젝트를 관리하는 스크립트, 미션 할당/완료 데이터가 어디에 있는지
4) 시야(POV 마스크, 2D Light)가 어떤 레이어/카메라로 렌더링되는지
5) 기존 UI Canvas 구조, CanvasScaler 설정, 현재 입력 처리 방식(Input Manager 축/버튼 목록)
6) 역할(포식자/피식자) 데이터가 어디에 저장되고 어떻게 동기화되는지
```

이어서 구현 방식을 2~3개 제안하고 장단점을 비교해줘. 내가 하나를 고르기 전에는 구현하지 마.
- A안: 맵 이미지를 미리 캡처해 둔 텍스처 + UI 마커 (어몽어스 방식. 가볍고 시야 시스템과 간섭 없음)
- B안: 전용 보조 카메라 + RenderTexture (맵이 바뀌어도 자동 반영, 2D Light/POV 마스크와의 간섭 주의)
- C안: 하이브리드
시야 시스템(2D Light, POV 마스크)이 미니맵 렌더링에 어떻게 영향을 주는지 반드시 짚어줘.

## 요구 기능 (방식이 정해지면 구현)

### 1. 표시 형태
- 코너 미니맵: 화면 우측 하단에 작게 표시. 위치(코너)와 크기는 인스펙터에서 조절 가능
  - 로컬 플레이어 중심으로 스크롤되는 방식, 줌 배율은 변수로 노출
- 전체 맵 오버레이: 키혹은 클릭 열고 닫음 (키세팅에 "Map" 버튼 추가, 기본 키 Tab)
  - 맵 전체가 한 화면에 보이도록 표시, 반투명 배경
  - 오버레이가 열려 있는 동안 플레이어 이동 가능
- 1920x1080 기준 CanvasScaler(Scale With Screen Size)로 해상도가 달라져도 비율 유지

### 2. 마커
- 로컬 플레이어 마커: 항상 표시. 빨간 점으로 표시
- 미션 마커: **로컬 플레이어에게 할당된 미션만** 표시. 완료되면 제거 노란 점으로 표시
- 다른 플레이어 마커: **기본값은 표시하지 않음.** 내 시야 안의 플레이어만 표시, 시야 공유 캐릭터의 경우 파트너 시야의 플레이어도 표시

### 3. 멀티플레이 규칙 (중요)
- 미니맵은 **클라이언트 로컬 UI**다. 서버 전용/헤드리스 실행에서는 생성하지 마
- 미니맵 때문에 다른 플레이어의 위치를 새로 네트워크 동기화하지 마.
  (전체 위치가 클라이언트에 노출되면 시야 시스템을 우회하는 치트가 가능해짐)
- 플레이어/미션 오브젝트가 스폰되거나 사라질 때, 늦게 접속(late join)하거나 재접속할 때
  마커가 올바르게 생성/제거되는지 확인
- 씬 전환, 라운드 재시작 시 마커가 중복되거나 남아 있지 않게 정리

### 4. 구현 규칙
- 매 프레임 메모리 할당 금지, 마커 오브젝트는 풀링
- 수치(크기, 줌, 마커 크기, 색상, 토글 키 등)는 [SerializeField]로 노출
- 기존 스크립트는 필요한 최소 범위만 수정하고, 미니맵 코드는 별도 폴더(예: Assets/Script/Minimap/)에 분리
- 맵 전체 경계(월드 좌표 → 미니맵 좌표 변환)는 하드코딩하지 말고 설정값으로 받기

### 5. 2차 기능 (이번 작업에서는 구현하지 마, 구조만 막지 않게)
- 탐험한 영역만 드러나는 안개(fog of war) 표시
- 사냥/미션 이벤트 시 마커 깜빡임이나 알림 연출

## 진행 방식
- 0단계 분석 보고 → 내가 방식 선택 → 구현 순서로 진행해줘.
- 구현은 아래 순서로 쪼개서, 각 단계가 끝날 때마다 확인받고 넘어가줘.
  1. 미니맵 기본 틀 (맵 표시 + 로컬 플레이어 마커)
  2. 코너 미니맵 스크롤/줌
  3. 전체 맵 오버레이 토글
  4. 미션 마커 (할당/완료 연동)
  5. 멀티플레이 검증 (Host + Client 2개 이상으로 스폰/해제/late join 확인)
- Unity MCP로만 GameObject/프리팹/UI를 만들고 수정해줘. .scene/.prefab YAML 직접 편집 금지.
- **MCP가 연결되지 않는 상태라면** 스크립트와 설정값 코드만 작성하고, 에디터에서 내가 직접 해야 할
  작업(Canvas 배치, 프리팹 연결, Input Manager 추가 등)을 번호 순서대로 정리해줘.
- 컴파일 에러가 없는 상태로만 단계를 마무리해줘.
- 각 단계가 끝나면 커밋 메시지를 `feat(minimap): 설명` 형식으로 제안하고 커밋해줘.
  push는 내가 확인한 뒤에만 해줘 (대상 브랜치: mainc).
- 작업 완료 후 Docs/progress/progress.md가 있으면 현재 상태 기준으로 갱신해줘.
