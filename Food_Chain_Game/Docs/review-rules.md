## 1. 세션 범위 규칙

- 한 세션에서는 **서로 의존성이 적은 시스템 하나**만 다룬다 (예: 시야 시스템, 네트워크 동기화, 미션 시스템 등을 섞지 않음)
- 한 세션에서 열어보는 스크립트는 **5~10개 이내**를 기본으로 하고, 그 이상이면 하위 주제로 더 쪼갠다
- 세션 시작 시 다룰 범위(폴더/시스템명)를 먼저 명시하고, 범위 밖 파일은 "관련 있어 보여도" 이번 세션에서는 훑지 않는다
- 이전 세션에서 발견된 이슈 중 이번 범위와 겹치는 게 있으면, review-notes.md에서 먼저 확인하고 시작한다

## 2. 점검 카테고리 및 등급

발견한 문제는 아래 4개 카테고리 + 3단계 등급으로 분류해서 기록한다.

**등급**
- 치명적 — 크래시, 데이터 손상, 치팅 가능, 네트워크 desync 유발
- 경고 — 당장 터지진 않지만 특정 조건에서 버그로 이어질 수 있음
- 제안 — 동작엔 문제없지만 유지보수성/성능 개선 여지

**카테고리별 체크리스트**

### A. 구조적 문제
- [ ] 한 클래스가 너무 많은 책임을 지고 있지 않은가 (God 클래스)
- [ ] 순환 참조나 스크립트 간 강한 결합이 있는가
- [ ] 싱글톤/정적 클래스를 과도하게 남용하고 있지 않은가
- [ ] 책임이 겹치는 두 스크립트가 같은 상태를 각자 관리하고 있지 않은가
- [ ] 네트워크 로직과 게임플레이 로직이 한 클래스에 뒤섞여 있지 않은가

### B. 버그 발생하기 쉬운 구조
- [ ] null 참조 가능성이 있는데 체크가 없는 곳
- [ ] `OnEnable`/`OnDisable`, 이벤트 구독/해제가 짝이 안 맞는 곳 (누수·중복 실행 원인)
- [ ] 코루틴이 `StopCoroutine` 없이 방치되거나, 오브젝트 파괴 시 정리 안 되는 곳
- [ ] **(네트워크 특화)** 클라이언트가 판정해서는 안 되는 로직(사냥 성공 여부, 미션 완료, 시야 판정)이 서버 검증 없이 클라이언트에서 그대로 처리되는 곳
- [ ] **(네트워크 특화)** SyncVar 갱신과 실제 게임 상태 변경 사이에 타이밍 차이로 인한 레이스 컨디션 가능성
- [ ] 타이머/프레임 기반 처리(공격 판정, 쿨다운 등)가 `Time.deltaTime`을 누락하거나 프레임 의존적으로 짜여있는 곳

### C. 최적화
- [ ] `Update()` 안에서 매 프레임 무거운 연산(정렬, LINQ, 문자열 처리 등)을 하는 곳
- [ ] `GetComponent`, `FindObjectOfType`, `GameObject.Find`를 캐싱 없이 반복 호출하는 곳
- [ ] `Instantiate`/`Destroy`를 빈번히 호출하는 곳 (오브젝트 풀링 후보)
- [ ] 불필요한 박싱/할당으로 GC 부담을 유발하는 패턴
- [ ] **(네트워크 특화)** SyncVar/ClientRpc/Command 호출 빈도가 과도해서 대역폭을 낭비하는 곳 (7인 이상 동시 플레이 기준으로 특히 중요)

### D. 리팩토링 대상
- [ ] 매직 넘버(의미 없는 하드코딩된 수치)
- [ ] 비슷한 로직이 여러 파일에 중복되어 있는 곳
- [ ] 네이밍이 일관되지 않거나 의도를 알기 힘든 변수/함수명
- [ ] 주석 처리된 죽은 코드, 사용 안 하는 필드/함수

## 3. 수정 진행 규칙

- 치명적 이슈는 **발견 즉시 사용자에게 먼저 보고**하고, 수정 방향에 대한 확인을 받은 뒤 진행한다 (바로 고치지 않음)
- 경고, 제안은 리스트로 모아서 세션 끝에 한 번에 보고한다
- 코드를 실제로 고칠 때는 한 번에 여러 파일을 대규모로 바꾸지 말고, 관련된 변경을 작은 단위로 나눠서 진행하고 각 단계 후 컴파일 확인
- 네트워크 동기화 관련 수정은 **반드시 실제 플레이 테스트가 필요하다는 점을 사용자에게 안내**하고 세션을 마친다 (자동으로 검증됐다고 단정하지 않음)

## 4. 기록 형식 (review-notes.md에 추가)

각 세션 종료 시 아래 형식으로 review-progress.md에 append한다.

```
## [YYYY-MM-DD] [시스템명] 리뷰

### 치명적
- [파일:라인] 문제 설명 → 조치 상태(수정함/보류/논의 필요)

### 경고
- [파일:라인] 문제 설명

### 제안
- [파일:라인] 제안 내용

### 다음 세션에서 볼 것
- (이번에 범위 밖이라 못 본 것, 후속 확인 필요한 것)
```

## 5. 세션 종료 체크리스트

- [ ] 발견한 이슈가 review-progress.md에 기록되었는가
- [ ] 치명적 이슈는 사용자와 논의 후 처리되었는가
- [ ] 이번에 수정한 코드가 컴파일되는가
- [ ] 네트워크/게임플레이 로직을 건드렸다면 실제 테스트 필요 여부를 안내했는가
- [ ] "다음 세션에서 볼 것" 목록이 남겨졌는가
