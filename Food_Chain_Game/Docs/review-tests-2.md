## 세션 6 — 미션 시스템 (개별 미션 구현체)

미니게임은 클라이언트 로컬에서만 진행되므로 인스턴스 1개(호스트)로도 확인 가능. 단, 미션 시작/완료 흐름 자체는 `review-tests.md` 5-1 ~ 5-4를 따른다.

### 6-1. 가방 이중 집계 (2026-10-09 수정)
- [ ] 열매 A: 열매를 가방에 **직접 끌어다 놓았을 때** 진행 표시가 1씩만 오르는지 (기존에는 한 번에 2 증가). 목표 4개를 전부 담아야 완료되는지
- [ ] 나뭇가지 B: 같은 방식으로 1씩만 오르고 목표 6개를 전부 담아야 완료되는지
- [ ] 열매 A / 나뭇가지 B: 아이템을 **던져서** 가방에 들어간 경우에도 1씩 정상 집계되는지
- [ ] 열매 A / 나뭇가지 B: 잡동사니(돌, 잎 등)를 가방에 넣어도 집계되지 않는지
- [ ] 풀 A: 정답 풀을 가방에 넣으면 "성 공", 오답을 넣으면 "실 패"가 한 번만 표시되고 정상 종료되는지

### 6-2. 시간 초과 처리 (풀 A, 씨앗 A, 씨앗 B)

- [ ] 타이머가 `0.0`에서 멈추고 `-0.0`이 보이지 않는지
- [ ] 시간 초과로 실패한 뒤 같은 미션을 바로 다시 시작할 수 있는지

### 6-3. 씨앗 A 숨기기

- [ ] 씨앗 4개를 전부 담으면 완료되는지

- [ ] 실패 후 미션 목록이 "미시작"으로 돌아가고, 같은 오브젝트에서 바로 다시 시작할 수 있는지

## 세션 7 — 게임 흐름 & 매니저

사망 처리 위치와 종료 판정이 바뀌었으므로 **호스트가 죽는 경우와 클라이언트가 죽는 경우를 모두** 확인한다.

### 7-1. 게임 도중 접속 종료/튕김 (2026-10-09 수정)
- 준비: 3명 이상(호스트 1 + 클라이언트 2). 나가는 쪽은 클라이언트
- [ ] 클라이언트 A가 게임 중 창을 닫으면 남은 사람 모두의 채팅창에 "A님이 게임에서 나갔습니다."가 뜨는지
- [ ] A의 플레이어 슬롯과 구역 패널 아이콘이 사라지고, A의 캐릭터가 맵에서 없어지는지 — **2026-10-09 변경: 살아 있던 플레이어가 나가면 사망 처리되어 그 자리에 시체가 남는다**(아래 8-6 참고)
- [ ] A가 나간 뒤에도 낮/밤이 계속 넘어가고, 밤 체크(굶주림·미션 실패)가 정상 처리되는지 — **기존에는 여기서 라운드가 멈췄음**
- [ ] 네트워크를 끊어 튕긴 경우(약 15초 뒤 감지)에도 위와 동일하게 처리되는지
- [ ] **유일한 포식자**가 나가면 게임이 바로 종료되고 결과 화면 → 로비 복귀가 되는지
- [ ] 피식자가 나가도 포식자가 남아 있으면 게임이 계속되는지
- [ ] 이미 죽은(유령) 플레이어가 나가도 게임 진행에 영향이 없고, 그 시체는 남아 있는지
- [ ] 타조/얼룩말 중 한 명이 나가면 남은 쪽의 공생 효과(밤 시야 보너스)가 해제되는지
- [ ] 미션 UI를 연 채로 나간 플레이어가 쓰던 미션을 다른 플레이어가 시작할 수 있는지

### 7-2. 로비 → 게임 → 로비 반복
- [ ] 정상 종료(마지막 날까지 진행) 후 로비로 돌아오고, 다시 시작해 두 번째 게임이 정상 진행되는지 (3회 이상 반복)
- [ ] 게임 중 한 명이 나간 판이 끝난 뒤 남은 인원이 로비로 정상 복귀하는지, 나간 사람의 색상이 풀려 있는지
- [ ] 나갔던 사람이 방 코드로 다시 들어와 다음 게임에 참여할 수 있는지
- [ ] 로비 복귀가 한 번만 일어나는지 (씬 전환 중복 에러가 콘솔에 없는지)

### 7-3. 게임 종료 판정
- [ ] 포식자가 전부 죽으면(공격 역공, 굶주림 포함) 게임이 끝나는지
- [ ] 밤 체크에서 마지막 포식자가 굶어 죽는 날, **같은 밤에 미션 실패로 죽는 피식자가 "패배"로 기록**되는지 (기존에는 승패가 먼저 계산돼 승리로 나왔음)
- [ ] 게임 종료 후 상단 표시가 "게임 종료"로 유지되고 다음 날 낮으로 바뀌지 않는지
- [ ] 생존자가 0명이 되면 게임이 끝나는지
- [ ] 결과 화면이 한 번만 뜨는지

### 7-4. 유령 상태
- 준비: 포식자 1 + 피식자 2 이상. 피식자 1명이 죽은 상태에서 확인
- [ ] 죽으면 반투명 유령이 되고, 벽·밤 맵 차단·하늘 구역 차단을 통과해 이동할 수 있는지 (맵 바깥 경계는 통과 불가)
- [ ] 살아있는 플레이어 화면에는 유령과 유령의 닉네임이 보이지 않고, 유령끼리는 서로 보이는지
- [ ] 유령의 일반 채팅과 말풍선이 유령에게만 보이는지 — **호스트가 살아있을 때 유령(클라이언트)의 말풍선이 호스트 화면에 뜨지 않는지** 반드시 확인
- [ ] 산 사람의 일반 채팅은 유령에게도 보이는지
- [ ] 귓속말: 유령↔유령, 산 사람↔산 사람은 전달되고, 산 사람→유령 / 유령→산 사람은 전달되지 않는지
- [ ] 죽은 포식자에게 킬 UI가 뜨지 않고 상호작용 키로 공격되지 않는지
- [ ] 죽은 조력자가 시체·조사 오브젝트에 상호작용할 수 없는지
- [ ] 죽은 피식자(오소리 제외)의 미션 목록이 비고, 미션 오브젝트가 하이라이트/상호작용되지 않는지
- [ ] 죽은 오소리는 미션 목록에 복수 미션만 보이고, 그 미션 오브젝트만 상호작용되는지
- [ ] 죽은 뒤 시체가 죽은 자리에 생기는지 (호스트가 죽을 때 / 클라이언트가 죽을 때 모두)

### 7-5. 전원 준비 후 시작 (2026-10-09 수정) — **3-9와 함께 가장 먼저 확인**
게임 시작 흐름이 바뀌었으므로 여기서 막히면 이후 항목은 테스트 불가.
- 준비: 3명 이상(호스트 1 + 클라이언트 2)
- [ ] 게임 씬 진입 후 **모든 인스턴스에서 거의 동시에** 캐릭터 소개 연출이 시작되는지 (먼저 로딩된 쪽이 혼자 먼저 재생하지 않음)
- [ ] 연출이 끝난 뒤(약 5초) 이동이 풀리고, 상단에 "1일차 낮"과 타이머가 표시되며 미션 목록이 채워져 있는지
- [ ] 각 인스턴스에서 플레이어 슬롯, 하늘 구역 차단(비행 불가 캐릭터), 시야 마스크가 정상 초기화되는지 — 클라이언트 쪽 필수 확인
- [ ] 한 클라이언트의 로딩을 일부러 늦췄을 때(에디터 일시정지 등) 나머지가 그 클라이언트를 기다렸다가 함께 시작하는지
- [ ] 준비를 기다리는 동안 한 명이 나가면 남은 인원으로 바로 시작되는지
- [ ] 한 명이 30초 넘게 준비되지 않으면 서버 콘솔에 경고가 뜨고 나머지 인원으로 시작되는지
- [ ] 연출 전 대기 중에는 공격/미션이 되지 않는지

### 7-6. 본인 승패 결과 (2026-10-09 수정)
- [ ] **클라이언트(호스트 아님)** 화면에서 승리한 플레이어에게 "승 리", 패배한 플레이어에게 "패 배"가 뜨는지 — 기존에는 클라이언트 승자도 "패 배"로 보였을 가능성이 큼
- [ ] 호스트 화면의 결과도 정상인지
- [ ] 죽은(유령) 플레이어에게도 결과 화면이 뜨는지
- [ ] 캐릭터별 결과가 승리 조건과 맞는지: 생존한 늑대/피식자 = 승리, 늑대가 살아있으면 까마귀 승리, 늑대가 죽었으면 하이에나 승리

### 7-7. 마지막 밤 이후 판정과 로비 복귀
- 준비: `maxRounds`를 1~2로 줄이면 빠르게 확인 가능
- [ ] 마지막 날 밤이 끝나면 굶주림·미션 실패 사망이 먼저 처리되고(시체 생성), 그 결과가 반영된 승패가 표시되는지 (마지막 밤에 미션 수가 모자란 피식자 = 패배)
- [ ] 결과 화면이 약 3초 표시된 뒤 전원이 로비로 돌아오는지
- [ ] 로비에서 다시 시작했을 때 7-5의 시작 흐름이 정상 반복되는지

### 테스트 전 준비 (세션 7 리뷰에서 확인된 환경 조건)
- [ ] **`Assets/StreamingAssets/config.json`을 만들 것.** `.gitignore`의 `*.json`에 걸려 저장소에 없으므로, 저장소를 받은 PC마다 직접 만들어야 함. 내용: `{"IP": "서버주소"}`. 없으면 방 생성/입장이 전부 실패함
- [ ] **1~2명 테스트는 에디터 또는 개발 빌드에서만 가능.** `RoomManager`의 `allowBelowMinPlayersForTest`(기본 켜짐)가 켜져 있어야 하며, 정식 빌드는 최소 3명. 방 정원은 실제 인원보다 크게 잡아도 됨
- [ ] **호스트는 Node(방 코드) 서버와 같은 기기에서 실행할 것.** 현재 코드는 호스트 주소로 `config.json`의 IP를 등록함(점검 A-3)
- [ ] **최소 3명으로 테스트할 것.** 캐릭터 풀이 고정 순서(타조 → 얼룩말 → 늑대 → 오소리 → 전갈 → 까마귀 → 스컹크 → 다람쥐 → 악어 → 여우)라 2명 이하에서는 포식자가 없고, 현재 코드상 포식자가 0명이면 첫 사망 즉시 게임이 종료됨. 전갈은 5명, 조력자(까마귀)는 6명부터 등장하므로 3-1(조사 오브젝트), 3-10(시체 조사), 4-1의 전갈 항목은 그 인원이 필요함. 인원이 모자라면 `RoomManager.GetCharacterPool`의 순서를 임시로 바꿔 테스트

## 멀티플레이 구조 점검 수정분 (2026-10-09)

### M-1. 로비 → 게임 → 로비 → 다시 시작
- 준비: 3명 이상(호스트 1 + 클라이언트 2)
- [ ] 최초 입장 시 **호스트에게만** 시작 버튼과 방 코드가 보이고, 클라이언트에게는 보이지 않는지
- [ ] 게임이 끝나 로비로 돌아왔을 때 호스트에게 **시작 버튼과 방 코드가 다시 보이는지** — 기존에는 나타나지 않았음
- [ ] 그 버튼으로 두 번째, 세 번째 게임이 정상 시작되는지
- [ ] 로비 복귀 시 **클라이언트 화면에서도** 모든 플레이어 캐릭터와 닉네임이 보이는지 (로딩이 느린 클라이언트 포함)
- [ ] 게임 씬에서는 로비 캐릭터(RoomPlayer)가 보이지 않는지

### M-2. 시작 조건
- [ ] 에디터에서 `allowBelowMinPlayersForTest`가 켜진 상태로 1명, 2명일 때 게임이 시작되는지
- [ ] `allowBelowMinPlayersForTest`를 끄고 2명일 때 시작 버튼을 누르면 "게임을 시작하려면 최소 3명이 필요합니다. (현재 2명)" 안내가 뜨고 시작되지 않는지
- [ ] 정원 7명 방에 3명만 있어도 시작되고, 캐릭터가 타조·얼룩말·늑대 중에서 배정되는지 (정원이 아닌 실제 인원 기준)
- [ ] 게임 중 한 명이 나가 인원이 줄어든 상태에서 로비 복귀 후, 최소 인원 이상이면 다시 시작되는지
- [ ] 시작 버튼을 빠르게 여러 번 눌러도 게임이 한 번만 시작되는지
- [ ] (정식 빌드) 2명일 때는 설정과 무관하게 시작되지 않는지

### M-3. 입장/퇴장 집계
- [ ] 게임 진행 중에 방 코드로 입장을 시도하면 거부되고(타이틀로 돌아감), 그 뒤 로비 복귀 후에는 정원까지 정상 입장되는지
- [ ] 위 시도를 여러 번 반복한 뒤에도 정원을 초과해 입장되지 않는지
- [ ] 정원이 찬 방에 입장을 시도하면 "방 인원이 가득 찼습니다." 안내가 뜨는지
- [ ] 로비에서 플레이어가 나갔다 들어오기를 반복해도 입장 가능 인원이 실제와 맞는지

### M-5. 끊김 사유 안내 / 나가기

## 세션 8-B — 로비·공용 UI (2026-10-09 수정)

### 8-8. 귓속말 — **2인 이상 필요**
- [ ] A가 B에게 귓속말을 보내면 **B 화면에 "A : 내용"**으로 표시되는지 (B 자신의 이름이 나오면 실패). A 화면에도 "A : 내용"
- [ ] B가 답장하면 양쪽 화면 모두 같은 탭에 "B : 내용"으로 이어지는지
- [ ] 귓속말 탭을 보고 있지 않을 때 탭 이름이 노란색으로 강조되고, 탭을 누르면 원래대로 돌아오는지(메시지가 여러 개 와도 이름이 깨지지 않는지)
- [ ] 귓속말 상대가 게임에서 나간 뒤 그 탭에서 글을 보내면 "귓속말 상대가 게임에 없습니다."만 뜨고 **전체 채팅에는 나타나지 않는지**

### 8-9. 채팅 입력과 이동
- [ ] 로비에서 채팅 입력 칸에 커서를 둔 채로 방장이 게임을 시작해도, 게임에서 바로 움직일 수 있는지 — **2인 필요(클라이언트 쪽에서 확인)**
- [ ] 게임 중 채팅 입력 중에 게임이 끝나 로비로 돌아왔을 때도 바로 움직일 수 있는지
- [ ] 엔터로 채팅 열기 → 입력 → 엔터로 전송 → 빈 채로 엔터 시 닫힘이 예전처럼 동작하는지
- [ ] 플레이어 목록에서 메모를 쓰고 엔터를 눌렀을 때 채팅 입력으로 넘어가지 않는지
- [ ] 채팅창이 꺼져 있을 때 엔터를 눌러도 이동이 막히지 않는지

### 8-10. 채팅 표시
- [ ] 채팅에 `<size=300>크게</size>`, `<color=red>빨강</color>`을 보내면 태그가 글자 그대로 보이는지(글자가 커지거나 색이 바뀌면 실패)
- [ ] 메시지를 100개 넘게 주고받아도 채팅이 느려지지 않고, 오래된 메시지부터 사라지는지
- [ ] 새 메시지가 오면 맨 아래로 스크롤되는지, 탭을 바꾸면 그 채널의 내용이 나오는지
- [ ] 마우스 휠: 채팅창 위에서만 채팅이 스크롤되고(한 번에 두 배로 움직이지 않는지), 다른 곳에서는 움직이지 않는지

### 8-11. 방 만들기 / 입장 (타이틀)
- [ ] 정원 드롭다운을 건드리지 않고 방을 만들었을 때 표시된 숫자와 실제 정원(입장 가능 인원)이 같은지 — Node 서버 필요
- [ ] 정원 7로 방을 만들고 → 타이틀로 나온 뒤 드롭다운이 7로 표시되고, 다시 만들면 정원이 7인지
- [ ] 닉네임이 없는 상태(첫 실행 또는 저장값 삭제)에서 닉네임 팝업을 ESC로 닫고 방 생성/입장을 누르면 팝업이 다시 뜨고 방에 들어가지지 않는지
- [ ] 방 생성/입장 버튼을 빠르게 여러 번 눌러도 정상적으로 한 번만 들어가지는지
- [ ] 없는 방 코드로 입장 실패 후 다시 입장을 시도할 수 있는지

### 8-12. 색상 버튼 — **2인 이상 필요**
- [ ] 게임이 끝나고 로비로 돌아온 직후, 다른 사람이 쓰는 색 버튼이 비활성화돼 있는지(M-7의 색 항목과 함께)
- [ ] 방을 나갔다가 다른 방에 여러 번 들어가도 고를 수 있는 색이 줄어들지 않는지

### 8-13. 기타
- [ ] 로비에서 방 코드 복사 직후 시작 버튼을 눌러 인원 부족 안내를 띄워도 문구가 2초간 유지되는지
- [ ] 캐릭터·오브젝트의 앞뒤 겹침(아래쪽에 있는 것이 앞에 그려짐)이 로비와 게임 모두 예전처럼 동작하는지, 게임 후 로비로 돌아와서도 유지되는지
- [ ] 플레이어 목록에서 나간 플레이어가 사라지고, 남은 슬롯의 우클릭 메뉴·메모가 정상인지

### 8-14. 로비 입장·퇴장 안내 (2026-10-09 수정) — **2인 이상 필요**
- [ ] 누군가 방에 들어오면 **방장이 아닌 플레이어 화면에도** "○○님이 입장하셨습니다."가 뜨는지 (들어온 본인 화면 포함)
- [ ] 누군가 로비에서 나가면 남은 모든 플레이어 화면에 "○○님이 퇴장하셨습니다."가 뜨는지
- [ ] 안내가 한 번씩만 뜨는지(방장 화면에 두 번 뜨면 실패)

### 8-15. 닉네임·채팅 태그 차단 (2026-10-09 수정) — **2인 이상 권장**
- [ ] 닉네임을 `<b>a</b>`처럼 태그로 지었을 때 머리 위 이름표·플레이어 목록·채팅에서 글자 그대로 보이는지(굵게 되면 실패)
- [ ] 채팅에 `<size=300>크게</size>`를 보냈을 때 **말풍선**에서도 글자 그대로 보이는지(로비, 게임 모두)
- [ ] `1 < 2`, `<3` 같은 평범한 글이 그대로 표시되는지(ㅁ 같은 깨진 글자가 끼지 않는지)
- [ ] 닉네임 8글자가 그대로 표시되고, 타이틀에서 9글자 이상은 저장되지 않는지

## 세션 9 — 설정 (2026-10-09 수정, 음성 제외)

### 9-1. 설정 창 열고 닫기
- [ ] 설정 값을 바꾸고 **X 버튼으로 닫은 뒤** 씬을 넘어가도(타이틀 → 로비 → 게임) 바꾼 값이 유지되는지 (예전 값으로 돌아가면 실패)
- [ ] ESC로 닫아도 같은 결과인지
- [ ] 타이틀에서 설정 창을 연 채 ESC를 누르면 설정 창만 닫히고 게임 종료 팝업은 뜨지 않는지. 한 번 더 ESC를 누르면 종료 팝업이 뜨는지
- [ ] 로비/게임에서 설정 창을 닫은 뒤 캐릭터가 정상적으로 움직이는지

### 9-2. 키 설정
- [ ] 키 변경 버튼을 누르고 다른 곳을 **마우스로 클릭해 취소**한 뒤에도 ESC로 설정 창을 닫고 다시 열 수 있는지 (ESC가 먹통이면 실패)
- [ ] 키 변경 버튼을 누르고 ESC를 누르면 지정이 취소되고(ESC가 키로 지정되지 않음) 설정 창은 닫히지 않는지
- [ ] 키를 꾹 누른 채로 변경 버튼을 누른 뒤 손을 떼도 그 키가 지정되지 않는지(새로 누른 키만 지정)
- [ ] 이미 다른 동작이 쓰는 키를 지정하면 두 동작의 키가 서로 바뀌는지
- [ ] 바꾼 키로 실제 이동·상호작용이 되고, 게임을 껐다 켜도 유지되는지
- [ ] "기본값 적용"이 동작하는지

### 9-3. 해상도 (빌드에서 확인)
- [ ] 해상도·화면 모드를 바꾸면 즉시 적용되고, 닫은 뒤 게임을 껐다 켜도 유지되는지
- [ ] 씬이 바뀔 때(타이틀 → 로비 → 게임) 화면이 깜빡이거나 해상도가 다시 설정되지 않는지
- [ ] 이전 버전에서 저장한 해상도가 있는 PC에서 처음 실행했을 때 엉뚱한 해상도가 되지 않는지

### 9-4. 소리
- [ ] 음량 슬라이더·숫자 입력·음소거가 예전처럼 동작하고 저장되는지 (현재 등록된 소리가 없어 UI 동작만 확인 가능)
- [ ] (2026-10-09 수정) 소리가 등록된 뒤: 전체 80 / 배경음 40일 때 배경음이 전체를 100으로 두고 배경음만 40으로 둔 것과 같은 크기로 들리는지(더 작게 들리면 실패). 전체를 배경음보다 낮게 내리면 배경음 슬라이더도 함께 내려가는지
- [ ] (2026-10-09 변경 감지 코드 삭제) 키·소리·해상도 설정의 변경, "기본값 적용", 닫을 때 저장이 예전처럼 동작하는지

## 음성(Vivox) (2026-10-09 구현) — **인스턴스 2개 이상 + 마이크 필요**

준비: 같은 PC에서 여러 개를 띄울 때는 소리가 섞이므로 헤드셋을 쓰거나, 가능하면 PC 2대로 확인. 화면 위쪽 가운데에 마이크 상태 표시가 있음.

### V-1. 로그인 / 같은 PC 다중 실행
- [ ] 인스턴스 2개를 띄웠을 때 콘솔의 `[VoiceManager] 로그인 완료. profile=..., voiceId=...`에서 **voiceId가 서로 다른지** (같으면 실패 → 서로 안 들림)
- [ ] 음성 서버에 연결하지 못하는 상태(인터넷 끊김)에서도 게임 진행이 막히지 않는지

### V-2. 로비
- [ ] 로비에서 멀리 떨어져 있어도 서로 목소리가 들리는지
- [ ] 나중에 들어온 사람과도 서로 들리는지, 나간 사람이 더는 들리지 않는지
- [ ] 설정 창의 음성 참가자 목록에 "Player"가 아니라 **닉네임**이 뜨는지, 개별 음량·음소거가 적용되는지

### V-3. 게임 중 생존자
- [ ] 게임 시작 직후 멀리 떨어진 플레이어의 목소리가 **안 들리는지**
- [ ] 화면에 보이는 거리보다 조금 더 멀어질 때까지 들리고, 더 멀어지면 서서히 작아져 안 들리는지
- [ ] 가까이 있어도 **벽 너머**면 안 들리고, 벽을 돌아 나오면 1초 안에 들리는지
- [ ] 밤에 시야가 좁아지면 들리는 범위도 같이 좁아지는지
- [ ] 설정 창의 참가자 개별 음량을 낮추면 게임 중에도 그 사람만 작게 들리는지(설정 창을 열어 둔 채로 거리에 따른 변화가 유지되는지)

### V-4. 유령
- [ ] 죽은 뒤 내 목소리가 **생존자에게 안 들리는지**
- [ ] 유령끼리는 거리와 상관없이 서로 들리는지
- [ ] 유령이 생존자 가까이 가면 그 생존자의 목소리가 들리고, 멀어지면 안 들리는지(벽 너머여도 가까우면 들림)
- [ ] 게임 도중 나간 플레이어의 목소리가 남지 않는지

### V-5. 게임 종료 / 방 나가기
- [ ] 게임이 끝나 로비로 돌아오면 다시 전원이 서로 들리는지(유령이었던 사람 포함)
- [ ] 방을 나가 타이틀로 가면 아무도 안 들리고, 콘솔에 Vivox 에러가 없는지
- [ ] 방을 나갔다가 다른 방에 들어가면 새 방 사람들과만 들리는지

### V-6. 마이크 방식 / 음소거
- [ ] 기본 상태(항상 켜짐)에서 키를 누르지 않아도 말이 전달되는지
- [ ] M 키 또는 상태 표시를 눌러 음소거하면 말이 전달되지 않고 표시가 "마이크 꺼짐"으로 바뀌는지, 다시 누르면 풀리는지
- [ ] 아래 버튼으로 "눌러서 말하기"로 바꾸면 V 키를 누르는 동안만 전달되는지, 말끝이 잘리지 않는지
- [ ] 채팅·닉네임 입력 중에 V, M을 쳐도 음성 상태가 바뀌지 않는지
- [ ] 방식(항상 켜짐/눌러서 말하기)이 게임을 껐다 켜도 유지되는지
- [ ] 상태 표시가 다른 UI(코드 표시, 게임 중 안내 문구 등)를 가리지 않는지 → 가리면 위치 조정 필요
- [ ] 설정 창의 음성 출력/입력 음량 슬라이더가 동작하는지(출력 음량이 예전보다 덜 줄어드는 것은 정상: 두 번 적용되던 것을 고침)

- [ ] 두 번째 사람이 들어와도 방장이 바뀌지 않는지
- [ ] 방장이 나가면 남은 사람 중 한 명이 방장이 되고 시작 버튼이 생기는지

## 해상도 대응 (2026-10-09 수정)

에디터에서는 게임 뷰 위쪽의 해상도 목록(Free Aspect 등)을 바꿔 가며, 빌드에서는 설정 창의 해상도·화면 모드를 바꿔 가며 확인.
권장 조합: 1920x1080, 1280x720, 2560x1440(16:9) / 1920x1200(16:10) / 1024x768(4:3) / 2560x1080(21:9).

### R-1. 화면별 배치
- [ ] 타이틀: 제목·버튼·닉네임 표시가 모두 보이고 눌리는지
- [ ] 로비: 방 코드, 게임 시작, 방 나가기, 색 선택(SET), 채팅, 마이크 표시(아래 가운데)가 서로 겹치지 않는지
- [ ] 게임: 남은 시간(위 가운데), 날짜(오른쪽 위, Scan 버튼 왼쪽), Scan 버튼, 프로필·해야 할 일, 미니맵, 메시지 버튼이 모두 보이는지
- [ ] 설정 창: 모든 탭의 내용이 창 안에 들어오고, 드롭다운 목록이 화면 밖으로 나가지 않는지
- [ ] 시작 연출·결과 화면·조사 목록·위장/예측 창·나가기 확인창이 화면 가운데에 온전히 보이는지

### R-2. 미션 (18종 전부, 최소 2개 해상도에서)
- [ ] 미션 창이 화면 가운데에 온전히 보이고, 물건·가방·도구가 창 안에 있는지
- [ ] 끌어서 옮기기: 물건이 마우스 커서를 정확히 따라오는지(커서와 어긋나면 실패)
- [ ] 가방/목표 지점 판정: 보이는 위치에 놓았을 때 들어가는지
- [ ] 던지기·자르기·낚시·그물·파리채·스캐너처럼 속도나 범위가 있는 미션이 1920x1080에서와 같은 난이도로 느껴지는지
- [ ] 고기 B: 고기 조각이 접시 위 제자리에 놓여 있는지
- [ ] 미션을 끝까지 완료/실패할 수 있는지

### R-3. 실행 중 해상도 변경 (빌드)
- [ ] 설정 창에서 해상도·화면 모드를 바꾼 직후 UI가 새 크기에 맞게 다시 배치되는지(미션을 연 상태에서도)
- [ ] 채팅창을 끌어 옮긴 뒤 해상도를 바꿔도 화면 밖으로 나가지 않는지
