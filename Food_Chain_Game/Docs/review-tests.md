# 리뷰 후 테스트 목록

리뷰 세션에서 수정한 내용 중 **실제 플레이로 확인해야 하는 항목**을 모아두는 문서.
리뷰가 전부 끝난 뒤 한 번에 테스트한다. 작성 규칙은 `review-rules.md` 6번 참고.

- 상태 표기: `[ ]` 미확인 / `[x]` 통과 / `[!]` 실패 (실패 시 항목 아래에 증상 기록)
- **통과한 항목은 이 문서에서 지운다.** 남아 있는 것은 아직 확인하지 못한 항목뿐이다. 단계별 진행 현황과 실패 항목은 `review-tests-2.md` 맨 위 "진행 현황" 참고 (2026-10-11 기준: 1단계 완료, 이 문서의 세션 3~5 항목은 2~5단계에서 확인 예정)
- 기본 환경: Multiplayer Play Mode 또는 ParrelSync로 인스턴스 2~3개 (호스트 1 + 클라이언트 1~2)
- 네트워크 관련 항목은 **호스트 쪽과 클라이언트 쪽 양쪽**에서 각각 확인

## 세션 3 — 상호작용 & 조사 오브젝트

### 3-1. 조사 오브젝트 탐색 서버 검증 (2026-10-09 수정)
- 준비: 조력자(까마귀 또는 물떼새) 1명 + 그 외 1명 이상. 조력자가 호스트인 경우와 클라이언트인 경우 둘 다 확인

### 3-2. 탐색 취소/실패 처리
- [ ] 탐색 대상이 진행 도중 게임에서 나가도 에러 없이 "탐색 실패"로 처리되는지

### 3-3. 이동/상호작용 잠금 (Modal Push/Pop 수정)
- [ ] 탐색 완료 후 미션을 열었을 때 미션 UI의 이동 잠금이 정상 유지되는지

### 3-4. 인스펙터 값
- [ ] `GamePlayer` 프리팹의 `investigationDuration`을 바꾸면 진행 바 시간과 실제 결과 도착 시간이 같이 바뀌는지

### 3-5. 우클릭 메뉴 스캔 서버 검증 (2026-10-09 수정)
- 준비: 스캔 가능 캐릭터(까마귀 또는 물떼새, 최대 2회) 1명 + 그 외 2명 이상. 호스트/클라이언트 양쪽 확인
- **보류:** 현재 스캔 버튼은 `IsExplorationPhase`일 때만 켜지는데 탐색 페이즈가 없어 항상 비활성. 스캔 전용 오브젝트 추가 작업(추후 예정) 이후에 아래 항목 테스트
- [ ] 다른 플레이어를 스캔하면 채팅에 "○○는 △△입니다."가 본인에게만 뜨고, 플레이어 슬롯의 이름 옆 동물 표시가 갱신되는지
- [ ] 2회 스캔한 뒤에는 스캔 버튼이 비활성화되고 3번째 결과가 오지 않는지
- [ ] 위장한 플레이어를 스캔하면 실제 동물이 아니라 위장한 동물로 표시되는지
- [ ] 스캔 직후 대상이 게임에서 나가도 스캔한 쪽 콘솔에 에러가 없는지
- [ ] 스캔 가능 캐릭터가 죽은 뒤에는 스캔 결과가 오지 않는지

### 3-6. 미션 시작/완료 서버 검증 (2026-10-09 수정)
- 준비: 피식자 2명 이상(호스트 1 + 클라이언트 1). **호스트가 아닌 클라이언트 쪽 미션을 반드시 확인** (서버 거리 판정이 호스트 화면의 미션 오브젝트 활성 상태와 무관하게 동작하는지 보기 위함)
- [ ] 미션 오브젝트를 **마우스 클릭**으로 열어도(트리거 영역 가장자리에서 클릭 포함) 완료가 정상 처리되는지 — 거부되면 `interactRange`(기본 4)가 작다는 뜻
- [ ] 모든 미션 종류(18개 오브젝트)에서 완료가 거부되지 않는지. 거부되면 클라이언트 콘솔에 `서버가 미션 완료를 거부함` 경고가 뜸

### 3-7. 사망자/모달 중 미션 차단
- [ ] 죽은 피식자(오소리 제외)가 미션 오브젝트를 마우스로 클릭해도 미션이 열리지 않는지
- [ ] 다른 창(미션, 탐색, 캐릭터 소개 등)이 열려 있는 동안 미션 오브젝트를 클릭해도 미션이 중복으로 열리지 않는지
- [ ] 죽은 오소리는 복수 미션(BadgerA)을 상호작용 키와 클릭 양쪽으로 시작/완료할 수 있는지

### 3-8. 완료 핸들러 1회 호출 (전갈)

### 3-9. 역할 정보 본인 전용 전달 (2026-10-09 수정) — **가장 먼저 확인**
게임 시작 흐름 전체에 영향을 주는 변경. 여기서 막히면 아래 항목들은 테스트 불가.
- 준비: 3명 이상(호스트 1 + 클라이언트 2), 포식자와 피식자가 섞이도록
- [ ] 밤이 됐을 때 **다람쥐**의 시야 반경이 11로 유지되는지 (포식자 6 / 그 외 8은 2026-10-11 확인. 다람쥐는 8명 이상이어야 등장)
- [ ] 피식자 클라이언트에서는 근처 플레이어에게 킬 UI가 뜨지 않는지 (포식자 클라이언트에서 킬 UI가 뜨고 공격되는 것, 대상이 죽으면 킬 UI가 꺼지는 것은 2026-10-11 확인)
- [ ] 미션 목록이 캐릭터에 맞게 배정되는지, 오소리/전갈/타조·얼룩말 능력이 이전과 동일하게 동작하는지

### 3-10. 시체 조사 서버 판정 (2026-10-09 수정)
- 준비: 조력자 1명 + 포식자 1명 + 피식자 1명 이상. 포식자가 피식자를 죽여 시체 생성
- [ ] 시체 조사 진행 중 조력자가 죽으면 진행 바가 즉시 사라지고 결과가 오지 않는지 (2026-10-11 수정: 사망 시 서버가 조사를 즉시 중단하고 클라이언트가 창을 닫음. 탐색 쪽은 확인 완료, 시체 조사 쪽은 미확인)

## 세션 4 — 포식자/피식자 능력 시스템

공격은 하루에 한 번(밤 체크 때 초기화)이라 조합마다 날짜를 넘기거나 게임을 다시 시작해야 함. 캐릭터 풀은 인원수 순서 고정(7인: 타조·얼룩말·늑대·오소리·전갈·까마귀·스컹크 / 9인부터 악어 / 10인 이상에서 매·하이에나·악어새)이라, 포식자 간 조합은 테스트용으로 풀을 임시 조정해야 확인 가능.

### 4-1. 공격 판정 규칙 (2026-10-09 수정) — 호스트/클라이언트 양쪽에서 공격자 역할 확인
피식자 대상
- [ ] 악어·하이에나가 **스컹크/여우/오소리**를 공격해도 대상이 죽는지 (기존에는 무반응이던 조합)

전갈 대상
- [ ] 매가 독 없는 전갈을 공격했을 때 매는 살고 전갈만 죽는지 (기존에는 둘 다 사망)

포식자끼리 (서열: 늑대 > 악어 > 매 > 하이에나)
- [ ] 서열이 높은 쪽이 낮은 쪽을 공격하면 대상이 죽는지 (예: 늑대→악어, 악어→매, 매→하이에나)
- [ ] 서열이 낮은 쪽이 높은 쪽을 공격하면 **공격자가 죽고** 대상은 사는지 (예: 매→악어, 하이에나→늑대, 악어→늑대, 하이에나→매)
- [ ] 위 경우 공격자의 시체를 조사하면 죽인 동물이 피격자(서열 높은 포식자)로 나오는지

공통
- [ ] 공격에 **실패**한 날에도 다시 공격되지 않는지 (공격 성공 후 같은 날 재공격 거부, 다음 날 다시 공격 가능은 2026-10-11 확인)
- [ ] 타조/얼룩말이 공격당하면 파트너 화면에 피격 알림이 뜨는지

### 4-2. 공격 서버 검증

### 4-3. 살해자 정보 / 채팅
- [ ] 오소리가 살해당한 뒤에도 복수 미션(BadgerA)이 정상적으로 목록에 뜨고 완료되는지 (동기화 제거 영향 확인)
- [ ] ★ 확인 필요: 이 항목은 원래 "산 플레이어→죽은 플레이어 귓속말은 정상 전달"이었으나, 현재 코드(`CmdSendWhisper`)와 7-4 항목은 산 사람↔유령 귓속말을 **양방향 모두 차단**한다. 2026-10-11 테스트에서도 전달되지 않았다(유령끼리·산 사람끼리는 전달됨). 차단이 의도라면 이 항목 삭제

### 4-4. 거주지 / 구역
- [ ] 게임 시작 시 구역 패널의 플레이어 아이콘이 각 캐릭터의 거주지에 놓이는지 (늑대·얼룩말·하이에나=들 / 악어·오소리·악어새=강 / 매·타조·까마귀=하늘 / 전갈·스컹크·다람쥐·여우=숲). 기존에는 대부분 숲에 놓였음
- [ ] 구역을 이동하면 아이콘이 해당 구역 패널로 옮겨지는지

### 4-6. 시체 사망 시각 표시 (2026-10-09 수정)
- 준비: 조력자 1명 + 포식자 1명 + 피식자 1명 이상. 화면 상단 타이머(남은 시간)를 보면서 진행

### 4-5. 위장 / 예측 (현재 해당 페이즈가 꺼져 있어 보류)
- **보류:** 위장·탐색 페이즈가 주석 처리돼 있어 UI로 진입 불가. 페이즈를 다시 켜면 아래 확인
- [ ] 여우의 위장 선택이 반영되는지 (임시로 여우만 위장 가능. 스컹크 포함 다른 캐릭터는 불가)
- [ ] 까마귀의 승자 예측이 기록되는지

## 세션 5 — 미션 시스템 (공통 구조)

미션 시작이 "서버 허용 응답을 받은 뒤 UI 실행"으로 바뀌었으므로 **3-6 ~ 3-8 항목도 이 흐름 기준으로 다시 확인**한다. 클라이언트(호스트 아님) 쪽 확인이 핵심.

### 5-1. 미션 시작 승인 흐름 (2026-10-09 수정)
- 준비: 피식자 2명 이상(호스트 1 + 클라이언트 1)

### 5-2. 다른 플레이어가 사용 중인 미션
- 준비: **같은 종류의 미션을 배정받은** 플레이어 2명 (배정이 무작위라 여러 번 시작해야 할 수 있음)

### 5-3. 최소 소요 시간 — **모든 미션 종류에서 확인 필요**
- [ ] 미션 18종을 각각 최대한 빠르게 클리어했을 때 완료가 **거부되지 않는지**. 거부되면 클라이언트 콘솔에 `서버가 미션 완료를 거부함` 경고가 뜨고 미션이 미시작으로 돌아감 → 해당 `MissionObject`의 `minDurationSeconds`(기본 2초)를 그 미션의 최단 클리어 시간보다 작게 조정

### 5-4. 완료/닫기 처리
- [ ] 죽은 오소리의 복수 미션(BadgerA)도 같은 흐름으로 시작/완료되는지 (전갈의 독 미션은 2026-10-11 확인)

### 5-5. 미션 종류 값 (enum 명시적 값)
- [ ] 미션 오브젝트 18개가 각각 맞는 미니게임을 여는지 (예: 풀 오브젝트 → 풀 미션). 값은 기존과 동일하게 부여했으므로 바뀌면 안 됨
