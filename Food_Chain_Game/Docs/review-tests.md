## 세션 3 — 상호작용 & 조사 오브젝트

### 3-1. 조사 오브젝트 탐색 서버 검증 (2026-10-09 수정)
- 준비: 조력자(까마귀 또는 물떼새) 1명 + 그 외 1명 이상. 조력자가 호스트인 경우와 클라이언트인 경우 둘 다 확인
- [ ] 조력자가 조사 오브젝트 옆에서 상호작용 키 → 대상 선택 → 확인 → 5초 뒤 결과(동물 종류, 포식자면 빨강/아니면 초록)가 표시되는지
- [ ] 탐색 결과가 조사 목록(InvestigationList)에 기록되는지
- [ ] 조력자가 아닌 캐릭터는 조사 오브젝트 옆에서 상호작용 키를 눌러도 탐색 창이 열리지 않는지
- [ ] 대상 선택 후 "취소"를 누르면 대상 목록이 다시 나오는지

### 3-2. 탐색 취소/실패 처리
- [ ] 탐색 진행(5초) 도중 조력자가 공격당해 죽으면 진행 바가 사라지고 "탐색 실패"가 표시되는지
- [ ] 탐색 진행 도중 창을 닫으면 결과가 나중에 뜨지 않는지
- [ ] 탐색 대상이 진행 도중 게임에서 나가도 에러 없이 "탐색 실패"로 처리되는지

### 3-3. 이동/상호작용 잠금 (Modal Push/Pop 수정)
- [ ] 탐색 창이 열려 있는 동안(대상 선택 중, 진행 중, 결과 표시 중) 이동과 상호작용이 막히는지
- [ ] 창을 닫으면 이동과 상호작용이 바로 풀리는지
- [ ] 탐색을 2~3회 연속으로 반복한 뒤에도 잠금이 남거나 미리 풀리지 않는지
- [ ] 탐색 완료 후 미션을 열었을 때 미션 UI의 이동 잠금이 정상 유지되는지

### 3-4. 인스펙터 값
- [ ] `GamePlayer` 프리팹의 `investigationDuration`을 바꾸면 진행 바 시간과 실제 결과 도착 시간이 같이 바뀌는지
- [ ] `InvestigationObject`의 `interactRange`(기본 2)가 `Scanner.scanRadius`(1.2)보다 작아지지 않게 설정돼 있는지 — 작으면 UI는 열리는데 서버가 바로 거부함

### 3-5. 우클릭 메뉴 스캔 서버 검증 (2026-10-09 수정)
- 준비: 스캔 가능 캐릭터(까마귀 또는 물떼새, 최대 2회) 1명 + 그 외 2명 이상. 호스트/클라이언트 양쪽 확인
- **보류:** 현재 스캔 버튼은 `IsExplorationPhase`일 때만 켜지는데 탐색 페이즈가 없어 항상 비활성. 스캔 전용 오브젝트 추가 작업(추후 예정) 이후에 아래 항목 테스트
- [ ] 다른 플레이어를 스캔하면 채팅에 "○○는 △△입니다."가 본인에게만 뜨고, 플레이어 슬롯의 이름 옆 동물 표시가 갱신되는지
- [ ] 2회 스캔한 뒤에는 스캔 버튼이 비활성화되고 3번째 결과가 오지 않는지
- [ ] 위장한 플레이어를 스캔하면 실제 동물이 아니라 위장한 동물로 표시되는지
- [ ] 스캔 직후 대상이 게임에서 나가도 스캔한 쪽 콘솔에 에러가 없는지
- [ ] 스캔 가능 캐릭터가 죽은 뒤에는 스캔 결과가 오지 않는지

### 3-6. 미션 시작/완료 서버 검증 (2026-10-09 수정)
- 준비: 피식자 2명 이상(호스트 1 + 클라이언트 1). **호스트가 아닌 클라이언트 쪽 미션을 반드시 확인** (서버 거리 판정이 호스트 화면의 미션 오브젝트 활성 상태와 무관하게 동작하는지 보기 위함)
- [ ] 미션 오브젝트 옆에서 상호작용 키로 미션을 열고 완료하면 미션 목록에 완료로 표시되고, 그 오브젝트가 비활성화되는지
- [ ] 미션 오브젝트를 **마우스 클릭**으로 열어도(트리거 영역 가장자리에서 클릭 포함) 완료가 정상 처리되는지 — 거부되면 `interactRange`(기본 4)가 작다는 뜻
- [ ] 모든 미션 종류(18개 오브젝트)에서 완료가 거부되지 않는지. 거부되면 클라이언트 콘솔에 `서버가 미션 완료를 거부함` 경고가 뜸
- [ ] 미션을 열었다 닫고 곧바로 다시 열어 완료해도 정상 완료되는지
- [ ] 미션을 닫으면 목록 상태가 "미시작"으로 돌아가고, 다시 시작할 수 있는지
- [ ] 미션 진행 중 죽으면 미션이 실패 처리되고 완료로 기록되지 않는지

### 3-7. 사망자/모달 중 미션 차단
- [ ] 죽은 피식자(오소리 제외)가 미션 오브젝트를 마우스로 클릭해도 미션이 열리지 않는지
- [ ] 다른 창(미션, 탐색, 캐릭터 소개 등)이 열려 있는 동안 미션 오브젝트를 클릭해도 미션이 중복으로 열리지 않는지
- [ ] 죽은 오소리는 복수 미션(BadgerA)을 상호작용 키와 클릭 양쪽으로 시작/완료할 수 있는지

### 3-8. 완료 핸들러 1회 호출 (전갈)
- [ ] 전갈이 독 미션을 완료하면 독을 얻고 독 미션 슬롯이 사라지는지
- [ ] 독을 가진 전갈이 공격당하면 공격자가 죽고, 독 미션 슬롯이 다시 생기는지
- [ ] 다음 날이 되면 독이 사라지고 독 미션 슬롯이 다시 생기는지

### 3-9. 역할 정보 본인 전용 전달 (2026-10-09 수정) — **가장 먼저 확인**
게임 시작 흐름 전체에 영향을 주는 변경. 여기서 막히면 아래 항목들은 테스트 불가.
- 준비: 3명 이상(호스트 1 + 클라이언트 2), 포식자와 피식자가 섞이도록
- [ ] 게임 씬 진입 후 **호스트와 각 클라이언트 모두** 자기 캐릭터 소개 연출(이름/거주지/승리 조건)이 정상적으로 나오는지
- [ ] 각자 콘솔에 `[GamePlayer] 내 캐릭터는 ○○`가 자기 캐릭터로 찍히는지
- [ ] 플레이어 슬롯에서 자기 이름 옆에는 자기 동물이, 다른 사람 옆에는 `???`가 표시되는지
- [ ] 비행 캐릭터(매/타조/악어새/까마귀)는 하늘 구역이 열려 있고, 아닌 캐릭터는 막혀 있는지 (`isFly`)
- [ ] 밤이 됐을 때 시야 반경이 캐릭터에 맞게 바뀌는지 (포식자 6 / 다람쥐 11 / 그 외 8)
- [ ] 포식자 클라이언트에서 근처 플레이어에게 킬 UI가 뜨고 공격이 되는지, 피식자 클라이언트에서는 안 뜨는지
- [ ] 조력자(까마귀/악어새) 클라이언트에서 시체·조사 오브젝트 상호작용이 되는지 (`canScan`)
- [ ] 미션 목록이 캐릭터에 맞게 배정되는지, 오소리/전갈/타조·얼룩말 능력이 이전과 동일하게 동작하는지
- [ ] 게임 종료 시 각자 승/패 결과가 정상 표시되는지
- [ ] 로비에서 게임 시작 → 종료 → 로비 복귀 → 재시작을 했을 때 두 번째 게임에서도 역할이 정상 배정되는지

### 3-10. 시체 조사 서버 판정 (2026-10-09 수정)
- 준비: 조력자 1명 + 포식자 1명 + 피식자 1명 이상. 포식자가 피식자를 죽여 시체 생성
- [ ] 조력자가 시체 옆에서 상호작용 키 → 3초 진행 바 → 결과(죽은 동물, 죽인 동물, N일차 낮/밤 N초)가 표시되는지
- [ ] 결과 값이 실제와 일치하는지 (죽인 동물이 실제 공격자, 굶어 죽은 경우 `???`)
- [ ] 결과가 조사 목록에 기록되고, 목록에서 다시 눌러 볼 수 있는지
- [ ] 이미 조사한 시체에 다시 상호작용하면 진행 바가 뜨지 않는지
- [ ] 진행 중 시체에서 멀어지면 진행 바가 사라지고 결과가 오지 않는지, 이후 이동/상호작용이 정상인지
- [ ] 진행 중 조력자가 죽으면 진행 바가 사라지는지
- [ ] 조력자가 아닌 캐릭터는 시체 옆에서 상호작용 키를 눌러도 아무 일도 없는지
- [ ] 조력자가 클라이언트(호스트 아님)일 때도 위 항목이 동일한지

## 세션 4 — 포식자/피식자 능력 시스템

공격은 하루에 한 번(밤 체크 때 초기화)이라 조합마다 날짜를 넘기거나 게임을 다시 시작해야 함. 캐릭터 풀은 인원수 순서 고정(7인: 타조·얼룩말·늑대·오소리·전갈·까마귀·스컹크 / 9인부터 악어 / 10인 이상에서 매·하이에나·악어새)이라, 포식자 간 조합은 테스트용으로 풀을 임시 조정해야 확인 가능.

### 4-1. 공격 판정 규칙 (2026-10-09 수정) — 호스트/클라이언트 양쪽에서 공격자 역할 확인
피식자 대상
- [ ] 늑대가 피식자(타조/얼룩말/까마귀/스컹크/오소리 등)를 공격하면 대상이 죽고 시체가 생기는지
- [ ] 악어·하이에나가 **스컹크/여우/오소리**를 공격해도 대상이 죽는지 (기존에는 무반응이던 조합)
- [ ] 공격에 성공한 포식자는 그날 밤 굶주림 체크를 통과하는지 (`hasEate`)

전갈 대상
- [ ] 독 없는 전갈을 공격하면 전갈만 죽고, 공격자는 포식 성공으로 처리되는지
- [ ] 독 있는 전갈을 공격하면 **전갈은 살고 공격자만** 죽는지 (기존에는 늑대가 공격하면 둘 다 사망)
- [ ] 독 반격 후 전갈의 독이 사라지고 독 미션이 다시 생기는지
- [ ] 매가 독 없는 전갈을 공격했을 때 매는 살고 전갈만 죽는지 (기존에는 둘 다 사망)

포식자끼리 (서열: 늑대 > 악어 > 매 > 하이에나)
- [ ] 서열이 높은 쪽이 낮은 쪽을 공격하면 대상이 죽는지 (예: 늑대→악어, 악어→매, 매→하이에나)
- [ ] 서열이 낮은 쪽이 높은 쪽을 공격하면 **공격자가 죽고** 대상은 사는지 (예: 매→악어, 하이에나→늑대, 악어→늑대, 하이에나→매)
- [ ] 위 경우 공격자의 시체를 조사하면 죽인 동물이 피격자(서열 높은 포식자)로 나오는지

공통
- [ ] 공격 후(성공/실패 모두) 같은 날에는 다시 공격되지 않고, 다음 날에는 다시 가능한지
- [ ] 타조/얼룩말이 공격당하면 파트너 화면에 피격 알림이 뜨는지

### 4-2. 공격 서버 검증
- [ ] 정상 거리(킬 UI가 뜨는 거리)에서의 공격이 **거부되지 않는지** — 거부되면 `GamePlayer` 프리팹의 `attackRange`(기본 3)가 작다는 뜻. 클라이언트가 공격자일 때 반드시 확인
- [ ] 게임 시작 직후 캐릭터 소개 연출 중(라운드 시작 전)에는 공격이 되지 않는지
- [ ] 게임 종료(결과 화면) 이후에는 공격이 되지 않는지

### 4-3. 살해자 정보 / 채팅
- [ ] 오소리가 살해당한 뒤에도 복수 미션(BadgerA)이 정상적으로 목록에 뜨고 완료되는지 (동기화 제거 영향 확인)
- [ ] 죽은 플레이어가 **살아있는** 플레이어에게 귓속말을 보내면 전달되지 않는지
- [ ] 죽은 플레이어끼리, 산 플레이어끼리, 산 플레이어→죽은 플레이어 귓속말은 정상 전달되는지
- [ ] 일반 채팅이 이전과 동일하게 동작하는지 (산 사람 채팅은 전원에게, 유령 채팅은 유령에게만)
- [ ] 200자를 넘는 채팅은 200자까지만 전달되고, 빈 메시지는 전송되지 않는지

### 4-4. 거주지 / 구역
- [ ] 게임 시작 시 구역 패널의 플레이어 아이콘이 각 캐릭터의 거주지에 놓이는지 (늑대·얼룩말·하이에나=들 / 악어·오소리·악어새=강 / 매·타조·까마귀=하늘 / 전갈·스컹크·다람쥐·여우=숲). 기존에는 대부분 숲에 놓였음
- [ ] 구역을 이동하면 아이콘이 해당 구역 패널로 옮겨지는지

### 4-6. 시체 사망 시각 표시 (2026-10-09 수정)
- 준비: 조력자 1명 + 포식자 1명 + 피식자 1명 이상. 화면 상단 타이머(남은 시간)를 보면서 진행
- [ ] 낮/밤 시작 직후(타이머가 거의 꽉 찼을 때) 죽인 시체를 조사하면 "N일차 낮/밤 **1~3초** 경과"처럼 작은 값이 나오는지
- [ ] 낮/밤이 거의 끝날 때(타이머가 몇 초 안 남았을 때) 죽인 시체는 낮/밤 길이에 가까운 큰 값이 나오는지
- [ ] 표시된 값 + 사망 당시 타이머의 남은 시간 ≈ 낮/밤 길이(낮 `dayRoundTime`, 밤 20초)인지
- [ ] 밤 체크에서 굶주림·미션 실패로 죽은 시체는 "밤 20초 경과"(밤 길이)로 나오는지
- [ ] 조사 오브젝트로 플레이어를 탐색한 기록의 시각도 같은 기준(경과 시간)으로 기록되는지

### 4-5. 위장 / 예측 (현재 해당 페이즈가 꺼져 있어 보류)
- **보류:** 위장·탐색 페이즈가 주석 처리돼 있어 UI로 진입 불가. 페이즈를 다시 켜면 아래 확인
- [ ] 여우의 위장 선택이 반영되는지 (임시로 여우만 위장 가능. 스컹크 포함 다른 캐릭터는 불가)
- [ ] 까마귀의 승자 예측이 기록되는지

## 세션 5 — 미션 시스템 (공통 구조)

미션 시작이 "서버 허용 응답을 받은 뒤 UI 실행"으로 바뀌었으므로 **3-6 ~ 3-8 항목도 이 흐름 기준으로 다시 확인**한다. 클라이언트(호스트 아님) 쪽 확인이 핵심.

### 5-1. 미션 시작 승인 흐름 (2026-10-09 수정)
- 준비: 피식자 2명 이상(호스트 1 + 클라이언트 1)
- [ ] 미션 오브젝트에서 상호작용 키/클릭 → 미션 UI가 정상적으로 열리는지 (클라이언트에서는 응답 왕복만큼 아주 짧은 지연 후 열림)
- [ ] 미션 UI가 열려 있는 동안 이동/상호작용이 막히고, 닫으면 바로 풀리는지
- [ ] 상호작용 키를 빠르게 연타해도 미션 UI가 한 번만 열리고 잠금이 꼬이지 않는지
- [ ] 미션 목록 UI에서 시작 시 "진행 중", 닫으면 "미시작", 완료하면 "완료"로 바뀌는지

### 5-2. 다른 플레이어가 사용 중인 미션
- 준비: **같은 종류의 미션을 배정받은** 플레이어 2명 (배정이 무작위라 여러 번 시작해야 할 수 있음)
- [ ] A가 미션 UI를 연 상태에서 B가 같은 미션 오브젝트에 상호작용하면 UI가 열리지 않고 채팅창에 "다른 플레이어가 사용 중인 미션입니다."가 뜨는지, B의 이동이 바로 풀리는지
- [ ] A가 미션을 닫거나 완료하면 B가 바로 시작할 수 있는지
- [ ] A가 미션 도중 **죽으면** B가 시작할 수 있는지
- [ ] A가 미션 도중 **게임에서 나가면**(강제 종료) B가 시작할 수 있는지 (끊김 감지까지 최대 15초)

### 5-3. 최소 소요 시간 — **모든 미션 종류에서 확인 필요**
- [ ] 미션 18종을 각각 최대한 빠르게 클리어했을 때 완료가 **거부되지 않는지**. 거부되면 클라이언트 콘솔에 `서버가 미션 완료를 거부함` 경고가 뜨고 미션이 미시작으로 돌아감 → 해당 `MissionObject`의 `minDurationSeconds`(기본 2초)를 그 미션의 최단 클리어 시간보다 작게 조정
- [ ] 거부된 뒤 같은 미션을 다시 시작해 정상 완료할 수 있는지

### 5-4. 완료/닫기 처리
- [ ] 미션 완료 후 다른 미션을 연달아 2~3개 진행해도 이동 잠금이 남거나 미리 풀리지 않는지 (Modal 이중 Pop 수정 확인)
- [ ] 완료한 미션의 오브젝트는 하이라이트되지 않고 상호작용 대상으로 잡히지 않는지
- [ ] 미션 진행 중 죽으면 미션 UI가 닫히고 완료로 기록되지 않는지
- [ ] 전갈의 독 미션, 죽은 오소리의 복수 미션(BadgerA)도 같은 흐름으로 시작/완료되는지

### 5-5. 미션 종류 값 (enum 명시적 값)
- [ ] 미션 오브젝트 18개가 각각 맞는 미니게임을 여는지 (예: 풀 오브젝트 → 풀 미션). 값은 기존과 동일하게 부여했으므로 바뀌면 안 됨
